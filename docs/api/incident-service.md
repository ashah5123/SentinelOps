# Incident Service API

Status: Foundation. This document describes the REST API implemented in Phase 3. Interactive,
always-current documentation is also served by the running service at `/swagger-ui.html`
(OpenAPI document at `/v3/api-docs`).

## ⚠️ Local-development security boundary

This phase implements **no authentication or authorization**. Every endpoint below is
reachable by anyone who can reach the port it is bound to. In the Compose environment it is
bound to `127.0.0.1` only — **never expose this API on a public or shared network.**
Authentication (Keycloak, OAuth 2.0/OIDC/JWT) is planned for a later phase; see
`docs/roadmap.md`.

## Base URL

`http://localhost:8081/api/v1/incidents` (port configurable via `INCIDENT_SERVICE_PORT`).

## Conventions

- All timestamps are ISO-8601 UTC.
- Errors are returned as [RFC 9457](https://www.rfc-editor.org/rfc/rfc9457) Problem Details
  (`application/problem+json`), each with a stable `errorCode` property — see
  [Error format](#error-format) below. No stack trace or internal database detail is ever
  returned.
- Every response carries an `X-Correlation-ID` header — either echoing the header the caller
  sent, or one generated by the service if none was provided.
- `POST /api/v1/incidents` requires an `Idempotency-Key` header (any client-generated unique
  string).

## Endpoints

### `POST /api/v1/incidents`

Creates a new incident. Requires `Idempotency-Key`.

```bash
curl -s -X POST http://localhost:8081/api/v1/incidents \
  -H 'Content-Type: application/json' \
  -H 'Idempotency-Key: 5c1e6b0a-8e0a-4a2e-9c1a-2a6f6a1a3fa8' \
  -d '{
        "title": "Checkout API returning elevated 5xx rate",
        "description": "p99 latency and 5xx rate on checkout-api exceeded SLO thresholds.",
        "severity": "SEV2",
        "source": "manual-report",
        "affectedService": "checkout-api",
        "detectedAt": "2026-09-12T18:04:00Z"
      }'
```

Returns `201 Created` with a `Location` header and the created incident. Repeating the exact
same request with the same `Idempotency-Key` returns the original `201` response again rather
than creating a second incident. Reusing the key with a different payload returns `409
Conflict` (`errorCode: IDEMPOTENCY_KEY_CONFLICT`). A missing key returns `400 Bad Request`
(`errorCode: IDEMPOTENCY_KEY_MISSING`).

### `GET /api/v1/incidents`

Lists incidents with pagination, filtering, and sorting.

Query parameters: `status`, `severity`, `affectedService`, `detectedFrom`, `detectedTo`
(all optional filters), `page`, `size`, `sort` (Spring pagination conventions — default sort is
`detectedAt,desc`, with `id` always appended as a deterministic tiebreaker).

```bash
curl -s "http://localhost:8081/api/v1/incidents?status=DETECTED&severity=SEV2&page=0&size=20"
```

### `GET /api/v1/incidents/{id}`

Returns a single incident. `404 Not Found` (`errorCode: INCIDENT_NOT_FOUND`) if it doesn't
exist; `400 Bad Request` (`errorCode: MALFORMED_REQUEST`) if `{id}` is not a valid UUID.

### `POST /api/v1/incidents/{id}/transitions`

Transitions an incident to a new status. Only transitions allowed by the lifecycle (see
`docs/architecture/system-overview.md` and `Incident`/`IncidentTransitions` in code) are
accepted.

```bash
curl -s -X POST http://localhost:8081/api/v1/incidents/{id}/transitions \
  -H 'Content-Type: application/json' \
  -d '{"status": "INVESTIGATING", "reason": "Paging on-call engineer"}'
```

An illegal transition returns `409 Conflict` (`errorCode: ILLEGAL_TRANSITION`) with `from` and
`to` properties on the problem detail.

### `POST /api/v1/incidents/{id}/evidence`

Records a piece of evidence against an incident. Returns `201 Created`.

```bash
curl -s -X POST http://localhost:8081/api/v1/incidents/{id}/evidence \
  -H 'Content-Type: application/json' \
  -d '{
        "evidenceType": "LOG_EXCERPT",
        "description": "checkout-api logs show connection pool exhaustion starting 18:03 UTC",
        "sourceReference": "https://loki.local/query?..."
      }'
```

### `GET /api/v1/incidents/{id}/timeline`

Returns the time-ordered list of status transitions and evidence for an incident.

### `GET /api/v1/incidents/{id}/audit-events`

Returns the paginated, immutable audit trail for an incident.

## Error format

Every error is a Problem Detail document:

```json
{
  "type": "https://sentinelops.dev/errors/ILLEGAL_TRANSITION",
  "title": "Conflict",
  "status": 409,
  "detail": "Cannot transition incident from RESOLVED to DETECTED",
  "instance": "/api/v1/incidents/1e6e0b9a-8e0a-4a2e-9c1a-2a6f6a1a3fa8/transitions",
  "errorCode": "ILLEGAL_TRANSITION",
  "timestamp": "2026-09-12T18:05:00Z",
  "from": "RESOLVED",
  "to": "DETECTED"
}
```

Stable `errorCode` values: `VALIDATION_ERROR`, `MALFORMED_REQUEST`, `INCIDENT_NOT_FOUND`,
`ILLEGAL_TRANSITION`, `IDEMPOTENCY_KEY_MISSING`, `IDEMPOTENCY_KEY_CONFLICT`,
`REQUEST_TOO_LARGE`, `INTERNAL_ERROR`.

## Request limits

Request bodies are limited to `sentinelops.incident-service.max-request-body-bytes` (default
1 MiB, configurable via `MAX_REQUEST_BODY_BYTES`). An oversized body is rejected with `413
Payload Too Large` (`errorCode: REQUEST_TOO_LARGE`).
