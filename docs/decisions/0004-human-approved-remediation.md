# 0004. Human-Approved Remediation

- Status: Accepted
- Date: 2026-09-12

## Context

SentinelOps investigates incidents and can recommend remediation
actions. Remediation actions act on real systems and can themselves
cause outages or data loss if wrong, especially given that root-cause
analysis is generated by an AI agent that can be mistaken. Fully
autonomous remediation would trade one class of incident risk for
another, less accountable one.

## Decision

SentinelOps will never execute a remediation or other operational
action automatically. Every remediation recommendation must pass
through a Human Approval Gate, where an authenticated, authorized
human operator explicitly approves or rejects the action before it is
allowed to execute. This is a hard architectural boundary enforced in
the platform, not a configuration toggle that can be disabled by a
deployer.

## Consequences

- The Investigation Agent's output is always framed as a
  recommendation with supporting evidence, never as a direct action.
- The Human Approval Gate and its audit trail are load-bearing
  components: their unavailability must block remediation (fail
  closed), per the failure-handling principles in the system overview.
- Every approved action must be attributable to a specific, identified
  human operator via the identity/authorization layer (Keycloak).
- This constrains product scope: SentinelOps is an investigation and
  recommendation platform with human-gated execution, not a fully
  autonomous remediation system, and should be described as such in
  all documentation and communication.
